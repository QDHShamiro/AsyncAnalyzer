# AsyncAnalyzer — detection benchmark

Generated by `python3 ml/benchmark.py`. Reproduce from a clean checkout with
`python3 ml/fetch_jars.py && python3 ml/benchmark.py`. CI reruns it on every push.

## Detection by behaviour

"Detected" means the behaviour is recognised. Only the unambiguous ones become an
accusation - the entity-sweep row is deliberately Review in the tool, because a
mob-radar minimap does exactly the same thing.

| cheat behaviour | detected | rule that catches it |
|---|:--:|---|
| KillAura | yes | rotation written **and** its own movement packet forged |
| Flight | yes | same fingerprint — forged movement |
| Pathing | yes | movement automation (Baritone-shaped) — forges its own movement |
| Timer | yes | several movement packets per tick |
| Loader | yes | decrypt **then** define a class |
| Esp | yes | render **and** a full entity sweep — surfaced for **review**, never accused |

### The line between automation and cheating

A legitimate auto-walk mod and a pathing cheat both move the player without
input. The difference is visible in the bytecode: the legit one drives the
game's own input system, the cheat writes the movement packet itself.

| jar | forges its own movement packet | verdict |
|---|:--:|---|
| Pathing (cheat) | yes | flagged |
| AutoWalk (clean) | no | clean |

## False flags on real software — the number that matters

Negative class: **174 real libraries** from Maven Central (ASM, ByteBuddy,
Netty, Guava, Kotlin, Spring, BouncyCastle, LWJGL — the library Minecraft
itself uses for input and OpenGL — mockito, log4j, …).

| | count |
|---|---:|
| real libraries tested | 174 |
| **flagged by a cheat rule (aim / esp / dropper)** | **0** |
| matched the Java-agent rule | 13 |

The agent matches are **correct, not false positives** — every one of these
genuinely ships instrumentation: `aspectjweaver-1.9.22.jar`, `byte-buddy-1.14.12.jar`, `byte-buddy-agent-1.14.12.jar`, `byte-buddy-dep-1.14.12.jar`, `h2-2.2.224.jar`, `javassist-3.30.2-GA.jar`, `jol-core-0.17.jar`, `kotlinx-coroutines-core-jvm-1.8.0.jar`, `mockito-core-5.11.0.jar`, `opentelemetry-javaagent-2.4.0.jar`, `pitest-1.16.1.jar`, `spring-context-6.1.6.jar`, `spring-instrument-6.1.6.jar`.
That rule is scoped to *a jar sitting in a mods folder*, where an agent is
abnormal; in an ordinary application classpath it is not.

## What these numbers do not say

- The cheat samples are **reconstructions** compiled from real open-source cheat
  client source (Meteor, Wurst), not captured cheat binaries. The constant pools
  come from a real compiler, so the structure is genuine, but a specific build of
  a paid client could differ.
- **ESP is not decidable from bytecode.** ESP and a mob-radar minimap perform the
  same operations. The tool surfaces that behaviour for review rather than
  accusing, and deciding it needs identity (hash verification), not a bigger model.
- A false-flag count of 0 means none of *these* 174 libraries were flagged.
  It is evidence, not a guarantee.

## End-to-end verdict — the whole chain, as a user sees it

Not just the behaviour rules: hash verification, the trained model, the hard
rules and the banding together.

| case | verdict | expected |
|---|:--:|:--:|
| a cheat jar, unverified | Confirmed | Confirmed/Likely |
| the same jar claiming to be 'sodium' | Confirmed | Confirmed |
| a real mod, hash-verified | Clean | Clean |
| a real mod from a mirror, unverified | Clean | Clean |
| an anticheat full of detection names | Clean | Clean |
| a random-named jar, nothing else | Review | Review |
| a random-named jar, verified | Clean | Clean |
| a mod with an injected agent | Confirmed | Confirmed |

Through the same full chain, **0 of 174** real libraries come out as anything
other than Clean.

## Team learning — does sharing scans actually help?

Simulating 15 rounds of a pattern the base model underrates, mixed with clean
scans so drift would show up:

| | before | after |
|---|---:|---:|
| score for the new cheat pattern | 13% | **35%** |
| worst score among clean scans | — | 9% (stays Clean) |
| a hard-confirmed cheat | — | Confirmed |

Learning is base-anchored, so it adapts without being able to drift into
flagging clean scans - which is the failure that would matter.
